# 2.12.2 — 2026-11-13

## Added

- **`pubmed_fetch_articles` returns `languages`, `vernacularTitle`, and `chemicals`** ([#295](https://github.com/cyanheads/pubmed-mcp-server/issues/295)) — `chemicals` (`name`, `ui`, `registryNumber`) comes with `includeMesh`, and each field has a `content[]` line. The added fields count toward `maxResponseCharacters`, so a budget sized to the earlier output can defer an article it used to fit.
- **`pubmed_fetch_articles` accepts `idType: "pmid"`** ([#243](https://github.com/cyanheads/pubmed-mcp-server/issues/243)) — the `pubmed_convert_ids` call shape; any other value is rejected.
- **`pubmed_convert_ids` and `pubmed_fetch_fulltext` read a DOI resolver link or `doi:` form as the bare DOI** ([#299](https://github.com/cyanheads/pubmed-mcp-server/issues/299)) — the advertised `dois` schema is unchanged.
- **`pubmed_fetch_fulltext` names the `sections` terms that matched nothing** ([#298](https://github.com/cyanheads/pubmed-mcp-server/issues/298)) — when a filter matches an article in part, the notice lists, per returned article, the terms that matched no title. Neither it nor the notice for a filter that matched nothing names an article `maxResponseCharacters` deferred; `deferred.ids` lists those.
- **`pubmed_fetch_citation_metrics` `includeClinicalCitations` returns `clinicalCitationPmids`** ([#300](https://github.com/cyanheads/pubmed-mcp-server/issues/300)) — uncapped, so off by default.

## Changed

- **Every `pmcUrl` uses `https://pmc.ncbi.nlm.nih.gov/articles/PMC…/`** ([#303](https://github.com/cyanheads/pubmed-mcp-server/issues/303)) — it was `www.ncbi.nlm.nih.gov/pmc/articles/…`; the RIS `UR` line already used the new host.
- **`pubmed_fetch_articles` rejects a `PMC`-prefixed ID or DOI in `pmids` with the route to `pubmed_convert_ids` or `pubmed_fetch_fulltext`.**
- **Unpaywall HTML extraction runs off the serving thread** ([#302](https://github.com/cyanheads/pubmed-mcp-server/issues/302)) — a worker per extraction, a 10 s deadline, two at a time per process. A page that runs past the deadline ends the tier as `parse-failed`, with that in `detail`.
- **`pubmed-guide` skill covers the PMID-only `pubmed_fetch_articles`, DOI link forms, `chemicals`, the partial-match notice, and `clinicalCitationPmids`.**
- **Test suite** — the failing-backend tests no longer depend on a cold sanitizer import under fake timers ([#306](https://github.com/cyanheads/pubmed-mcp-server/issues/306)), and the citation-formatter linear-time rows take fewer readings ([#304](https://github.com/cyanheads/pubmed-mcp-server/issues/304)).

## Fixed

- **A Europe PMC call ends at one total deadline, `EUROPEPMC_TOTAL_DEADLINE_MS` (default `45000`)** ([#305](https://github.com/cyanheads/pubmed-mcp-server/issues/305)) — it covers the call's queue wait, retries, and backoff, and ends as the retryable `europepmc_deadline_exceeded`. A call to a Europe PMC that never answered ran 85–89 s, past an MCP client's default 60 s request timeout, and failed with no reason. `pubmed_find_related` failed-chain attempts report that reason for a Europe PMC deadline expiry, where they reported `timed_out`.
- **Unpaywall HTML extraction's diagnostic output goes to stderr** — it went to stdout, where the stdio transport carries protocol messages.

## Security

- **DOI validation on `pubmed_convert_ids` and `pubmed_fetch_fulltext` runs in time linear in the input's length.**
