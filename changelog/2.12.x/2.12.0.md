# 2.12.0 — 2026-11-02

## Added

- **`pubmed-guide` agent skill** — listed in `resources/list` as `skill://pubmed-guide/SKILL.md`, served through `createApp({ skills: 'skills' })`, and named in the server `instructions`. It covers PubMed query syntax, DOI-to-PMID routes outside PMC, reference-list resolution, citation counts, and full-text misses, and ships in the npm package, plugin installs, the `.mcpb` bundle, and the Docker image.
- **`pubmed_search_articles` filter-only search** ([#245](https://github.com/cyanheads/pubmed-mcp-server/issues/245)) — `query` is optional; omitted or empty, the search runs on `author`, `journal`, `meshTerms`, or `publicationTypes` alone (`all[sb]` selects the whole database for a slice by the other filters). A call with no query and no subject filter fails as the new `no_search_term` (`ValidationError`, not retryable); a `query` holding no term is still `blank_query`. `output.query` is empty and `effectiveQuery` is the filter clauses joined by `AND`; an empty result reads "No results matched the applied filters".

## Changed

- **Page sizes past the per-call cap are served at the cap** ([#232](https://github.com/cyanheads/pubmed-mcp-server/issues/232)) — `pubmed_search_articles` `maxResults` (1,000) and `summaryCount` (50), `pubmed_find_related` `maxResults` (50), `pubmed_lookup_mesh` `maxResults` (50), and `pubmed_europepmc_search` `pageSize` (100) accept up to ten times the cap, and a clamped call adds a `notice` naming where to continue (`offset`, `nextOffset`, `nextCursorMark`, or `pubmed_fetch_articles` and its 200-PMID limit per call). Values past ten times the cap are still rejected. `pubmed_find_related` `offset` now says to step by the number of articles returned, not `maxResults`.
- **Test suites** ([#275](https://github.com/cyanheads/pubmed-mcp-server/issues/275), [#276](https://github.com/cyanheads/pubmed-mcp-server/issues/276)) — timing tests use fake timers and a shared CPU-time measure, and `readCommonMark` carries link targets, code and HTML block bodies, heading levels, and break kinds.

## Fixed

- **E-utilities requests missing from `http.client.request.duration`** ([#281](https://github.com/cyanheads/pubmed-mcp-server/issues/281)) — eutils GET and POST and the PMC ID Converter GET now record each attempt on the framework's histogram, with the method, host, and status when a response arrived.
- **Keyed NCBI request gap** ([#280](https://github.com/cyanheads/pubmed-mcp-server/issues/280)) — the default with `NCBI_API_KEY` is 120 ms, up from 100 ms at NCBI's 10 req/s ceiling; an unsubstituted `${…}` placeholder for `NCBI_REQUEST_DELAY_MS` reads as unset, so a keyed server takes 120 ms there too.
- **`pubmed_fetch_citation_metrics` retry advice** ([#278](https://github.com/cyanheads/pubmed-mcp-server/issues/278)) — an iCite record for a PMID the call did not request fails as the new non-retryable `icite_unrequested_record`, whose recovery says to fetch in smaller batches; `icite_invalid_response` keeps the unparseable-body case and its retry advice.
- **`pubmed_europepmc_search` cursor on the last page** ([#283](https://github.com/cyanheads/pubmed-mcp-server/issues/283)) — a page shorter than `pageSize` carries no `nextCursorMark`. A walk whose hit count is an exact multiple of `pageSize` still gets a cursor on its last full page; the field description says so, and the empty page it leads to carries a notice naming the total.
- **`pubmed_find_related` request-cap notice** ([#284](https://github.com/cyanheads/pubmed-mcp-server/issues/284)) — a fallback walk that stopped at its request cap says so without advice when it found no PMID, keeps "lower the offset" when the offset lies past the rows found, and names the rows the page holds out of those requested when it is partial.
