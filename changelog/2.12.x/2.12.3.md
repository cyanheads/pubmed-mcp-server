# 2.12.3 — 2026-11-21

## Added

- **`pubmed_search_articles` summaries and `pubmed_find_related` rows carry `languages`** ([#309](https://github.com/cyanheads/pubmed-mcp-server/issues/309)) — the ESummary `Lang` codes in NCBI's order, as `pubmed_fetch_articles` returns them, and in `content[]`. Absent on a row ESummary did not describe.

## Changed

- **`NCBI_TOTAL_DEADLINE_MS` defaults to `50000`** ([#310](https://github.com/cyanheads/pubmed-mcp-server/issues/310)) — it was `60000`. A tool call as a whole runs under 50 s, or the larger of this and `EUROPEPMC_TOTAL_DEADLINE_MS` when either is set higher; a value below 50 s still ends the NCBI call at its own.
- **`EUROPEPMC_MAX_RETRIES` and `EUROPEPMC_TIMEOUT_MS` also set OpenAlex and iCite requests, and `EUROPEPMC_TOTAL_DEADLINE_MS` also bounds OpenAlex calls** ([#310](https://github.com/cyanheads/pubmed-mcp-server/issues/310)) — iCite keeps a fixed 50 s deadline. `.env.example` and the README env table say so.
- **`pubmed_find_related` names the provider in a timeout or rate-limit reason** — `attempted[]` and `coverageFailures[]` report an NCBI timeout as `ncbi_timed_out`, a Europe PMC timeout as `europepmc_timed_out`, and a Europe PMC rate limit as `europepmc_rate_limited`, where they read `timed_out`, `timed_out`, and `rate_limited`.
- **`pubmed-guide` skill 1.0 → 1.1** — covers `languages`, the `pubmed_spell_check` notice, and the 50 MiB and deadline outcomes of `pubmed_fetch_fulltext`.

## Fixed

- **A tool call settles under one 50 s deadline** ([#310](https://github.com/cyanheads/pubmed-mcp-server/issues/310)) — handlers start it, and every upstream call runs under the smaller of its provider's deadline and the time left. Against hung upstreams a call ran up to 192 s (`pubmed_find_related`), past an MCP client's 60 s default.
- **Chains report what the deadline left out** ([#310](https://github.com/cyanheads/pubmed-mcp-server/issues/310)) — `pubmed_find_related` reports a provider with no time left as `not_reached` and sends the rows without ESummary metadata, under a notice; `pubmed_fetch_fulltext` reports a tier with no time left as `not-attempted`, and a tier the deadline cut carries the provider's `*_deadline_exceeded` reason in its `detail`.
- **OpenAlex calls run under a total deadline** ([#310](https://github.com/cyanheads/pubmed-mcp-server/issues/310)) — expiry ends as the retryable `openalex_deadline_exceeded`.
- **iCite ends a fired deadline as `icite_deadline_exceeded` and attempts that end on a timeout as `icite_timed_out`** ([#310](https://github.com/cyanheads/pubmed-mcp-server/issues/310)) — `retry_deadline_exceeded` no longer reaches a caller.
- **A caller's cancellation is rethrown with the caller's reason** ([#310](https://github.com/cyanheads/pubmed-mcp-server/issues/310)) — in `pubmed_fetch_fulltext` where a step is skipped for time, and before landing-page extraction starts.
- **Unpaywall content reads stop at 50 MiB** ([#311](https://github.com/cyanheads/pubmed-mcp-server/issues/311)) — a PDF or landing page over the limit is a `fetch-failed` miss with the limit named in the `unpaywall` tier `detail`. An over-limit `url_for_pdf` falls through to the landing page, unless both are the same address.
- **An EFetch HTTP 400 carrying a truncated result document is retried** ([#314](https://github.com/cyanheads/pubmed-mcp-server/issues/314)) — it ends as `ncbi_unreachable` once retries run out, where it was an unretried `InvalidParams` with no reason.
- **A Europe PMC call whose attempts end in a timeout or HTTP 504 carries `europepmc_timed_out`** ([#315](https://github.com/cyanheads/pubmed-mcp-server/issues/315)) — with each Europe PMC tool's outage recovery on both surfaces.
- **`pubmed_spell_check` drops a replacement PubMed barely holds** ([#316](https://github.com/cyanheads/pubmed-mcp-server/issues/316)) — one with under a tenth of the caller's word's records is dropped (`tirzepatide` stays, where ESpell returned `irzepatide`), unless ESpell's MeSH dictionary offers a spelling with more records (`tirzepatid` → `tirzepatide`). The checks send at most 12 NCBI requests within 10 s, and a check that cannot run is named in `notice`.
- **An NCBI HTTP 504, 408, or 425 that ends a call carries `ncbi_timed_out`** — a retryable `Timeout`, where it had no reason.
- **A Europe PMC HTTP 429 that ends a call carries `europepmc_rate_limited`** — retryable, with `retryAfter` kept.
- **`authors` is omitted on a search summary or related-article row that credits no one** — it was an empty string.
- **NCBI answers that parse but are not the answer end as `ncbi_invalid_response`** — an ESearch result with no `eSearchResult` element or no numeric `Count`, and an ESpell answer with no `eSpellResult` element, read as a `TypeError`, zero records, and no correction.
- **`pubmed_find_related` accepts a Bookshelf book as the source PMID** — it was reported as not found, since ESummary gives a book no `Title`; the source lookup now reads the version 2.0 ESummary and its `BookTitle`.
- **`pubmed_fetch_fulltext`'s no-body notice for a PMCID names `pubmed_convert_ids`** — `pubmed_fetch_articles`, which the notice points to, takes PMIDs only.
