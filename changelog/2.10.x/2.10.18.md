# 2.10.18 — 2026-09-22

## Fixed

- **The unkeyed `NCBI_REQUEST_DELAY_MS` default rises from 334ms to 400ms.** 334ms sat exactly at NCBI's 3 req/s ceiling with no margin for arrival jitter, so an ordinary burst of concurrent calls drew 429s that chased the retry queue's cooldown gate; an explicit override still takes precedence. [#162](https://github.com/cyanheads/pubmed-mcp-server/issues/162)
- **Europe PMC's request queue moves onto the framework pacer.** A retrying call held one of the queue's four concurrency slots through every backoff sleep and skipped the start gap on retries. Every attempt now re-queues and re-paces from the shared last-dispatch time, so backoff no longer stalls other callers, including `pubmed_fetch_fulltext`'s parallel Europe PMC tier. [#163](https://github.com/cyanheads/pubmed-mcp-server/issues/163)
- **OpenAlex's exhausted-retry error only stamps `openalex_unreachable` on a `ServiceUnavailable`.** A `Timeout` or `RateLimited` now keeps its own code with no reason and its upstream `retryAfter`, where every exhausted error previously carried the `ServiceUnavailable`-only reason and lost `retryAfter`. `pubmed_find_related`'s coverage summary now labels a reasonless provider failure by its code (`rate_limited`, `timed_out`) instead of `unclassified_error`. [#160](https://github.com/cyanheads/pubmed-mcp-server/issues/160)
