# 2.10.19 — 2026-09-27

## Added

- **`commentsCorrections[]` on `pubmed_fetch_articles`** ([#178](https://github.com/cyanheads/pubmed-mcp-server/issues/178)) — the notices NCBI links from `CommentsCorrectionsList` (`refType`, `refSource`, optional `pmid` and `note`), `Cites` entries excluded, in NCBI's order. `content[]` lists them under `#### Comments and Corrections (N)` ahead of the abstract; the field is absent when a record links nothing else.
- **`ncbi_rate_limited`** (`RateLimited`, retryable) in the NCBI error contract, which `pubmed://database/info` now declares too — an NCBI 429 the call stops on carries it with NCBI's `retryAfter`, and its hint names `NCBI_API_KEY` as an operator setting.

## Changed

- **`pubmed_lookup_citation` advertises `citations` as `type: "array"` (1–25) again** ([#173](https://github.com/cyanheads/pubmed-mcp-server/issues/173)) — a lone citation object, or one sent as `citation`, is wrapped into a one-element array before validation, so a field error names its element (`citations.0.journal`).
- **An NCBI JSON `error` field arrives as `data.ncbiErrors: [message]`**, as an XML `<ERROR>` does, in place of `data.ncbiError`.
- **Cancelling `pubmed_fetch_fulltext` or `pubmed_find_related` ends the call** instead of falling through to the next full-text tier or related-articles provider.
- **Error envelopes carry `data.requestId`, and a tool error's `content[]` ends with `request <id>`** (mcp-ts-core 0.13.10). Error `data` no longer carries server stack traces or request-context fields such as `operation` (mcp-ts-core 0.13.7, 0.13.8).
- **An integer sent for a string field, or a JSON-stringified object, is repaired before validation**, and a rejection names the alias rewrite it applied (`Validated limit as maxResults.`) (mcp-ts-core 0.13.9).
- **Streamable HTTP refusals** (MCP SDK 2.1.0, via mcp-ts-core 0.13.9) — a 2026-07-28 POST without `MCP-Protocol-Version` is refused `400` / `-32020`, and a JSON-RPC batch of more than 100 messages `400` / `-32600`.
- **Docker image** — production dependencies install in a `$BUILDPLATFORM` deps stage through `scripts/install-otel.ts`; the image gains a `HEALTHCHECK` on `/healthz` and an `org.opencontainers.image.version` label from `APP_VERSION`, and drops `MCP_FORCE_CONSOLE_LOGGING`.
- **Docs:** the README's tool table and capability reference are condensed to what each tool does and its limits; `.env.example` documents the Europe PMC settings and `NCBI_TOOL_IDENTIFIER`; `framework-skills/` synced to mcp-ts-core 0.13.10.

## Fixed

- **An NCBI call that stops short of its deadline reports its last attempt** ([#174](https://github.com/cyanheads/pubmed-mcp-server/issues/174)) — `ncbi_unreachable` with NCBI's message, `ncbiErrors`, and `attempts` when the next backoff would not fit. A real expiry stays `ncbi_deadline_exceeded` and now keeps `ncbiErrors`; its hint leads with a retry and names batch size only for a large batch.
- **A one-source `pubmed_europepmc_search` filter keeps `EXT_ID` matches** ([#175](https://github.com/cyanheads/pubmed-mcp-server/issues/175)) — a single source is sent as `SRC:"X" OR SRC:"X"`, so a quoted or unquoted `EXT_ID` lookup matches.
- **An unreadable `cursorMark` is reported as bad input, not an outage** ([#180](https://github.com/cyanheads/pubmed-mcp-server/issues/180)) — a second HTTP 503 on a caller's cursor, while the first page of the same query is served, fails as non-retryable `europepmc_invalid_input` naming `cursorMark`.
- **Newly rejected inputs** — each used to reach the upstream and return unfiltered results, a false empty result, or an outage ([#176](https://github.com/cyanheads/pubmed-mcp-server/issues/176), [#177](https://github.com/cyanheads/pubmed-mcp-server/issues/177)):
  - `pubmed_search_articles` `blank_filter`: an `author`, `journal`, or `language` value, or a `publicationTypes` / `meshTerms` element, of only whitespace, invisible characters, markup, `()`, `[]`, or `""`. `data.fields` names each (`meshTerms.1`); an exactly-empty string still sets no filter.
  - `pubmed_search_articles` `invalid_date_range`: a `dateRange` bound that is no real calendar date (`2023/02/29`, month `13`, day `00`), or a `minDate` after `maxDate` once PubMed expands each partial date.
  - `pubmed_search_articles`, `pubmed_spell_check`, `pubmed_lookup_mesh` `blank_query`: a `query` of only invisible characters, such as a zero-width space.
  - `pubmed_europepmc_search` `blank_query`: a `query` with no term (`"   "`, `()`, `<b></b>`, `&nbsp;`). `blank_cursor`: a `cursorMark` of only whitespace or invisible characters.
- **Minor:** an exhausted retry after one attempt reads `(failed after 1 attempt)`; `europepmc_invalid_input` errors carry `retryable: false`; the `openalex_invalid_response` contract declares `ServiceUnavailable`, the code it is thrown with.
