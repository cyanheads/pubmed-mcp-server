# 2.10.15 — 2026-09-22

## Fixed

- **EFetch's `proxy_stream()` backend relays now retry as `ncbi_unreachable`** instead of a bare HTTP 400 — the same envelope NCBI's backend proxy prefixes onto a relayed 502 page or a "Failed to connect to PubOne service" message. [#155](https://github.com/cyanheads/pubmed-mcp-server/issues/155)
- **An all-invalid EFetch ID list (`id=00000000`, `pubmed`/`pmc` only) now resolves as the empty set NCBI returns for a well-formed but unknown ID**, instead of an `ID list is empty!` error. [#155](https://github.com/cyanheads/pubmed-mcp-server/issues/155)
- **The NCBI request queue is rebuilt on the framework pacer**, closing one shared cooldown gate for every queued caller on an NCBI 429 instead of each caller retrying independently into the same throttle. Each retry attempt now re-queues and re-paces under one deadline covering queue wait, attempts, and backoff; a call that cannot start in time sheds as `queue_full` with `retryAfter`. [#157](https://github.com/cyanheads/pubmed-mcp-server/issues/157)
- **A failed Europe PMC `/search` (404 or a retryable 5xx) now retries as `europepmc_unreachable`** instead of surfacing the bare upstream status — a search failure is an outage, not "no match"; a genuine zero-hit query stays HTTP 200. [#152](https://github.com/cyanheads/pubmed-mcp-server/issues/152)
- **Europe PMC's intermittent empty `{version}` envelope now retries as transient upstream noise** instead of failing fast as invalid input. Only a `sort` naming an undocumented field or direction, or a `cursorMark` that draws the envelope through every retry attempt, still fails fast — attributed to that input specifically. [#159](https://github.com/cyanheads/pubmed-mcp-server/issues/159)
