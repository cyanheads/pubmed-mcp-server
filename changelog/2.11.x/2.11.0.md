# 2.11.0 — 2026-10-25

## Added

- **Added `pubmed_fetch_citation_metrics` (NIH iCite RCR, NIH percentile, citation counts)** ([#266](https://github.com/cyanheads/pubmed-mcp-server/issues/266)) — takes up to 1,000 `pmids` (alias `ids`) and fetches the first 200 distinct in one iCite request, returning the rest in `overLimit`. Records carry the Relative Citation Ratio with a provisional flag, citation counts and rates, Approximate Potential to Translate, MeSH category shares, and clinical citations; PMIDs iCite has no record for land in `unavailablePmids`.
- **`pubmed_fetch_fulltext` `sectionCap`** ([#268](https://github.com/cyanheads/pubmed-mcp-server/issues/268)) — when `maxSections` drops top-level sections from a `source: "pmc"` article, `sectionCap` lists the omitted titles and labels per article, `truncated` is `true`, and the notice points to `sections` or a larger `maxSections`.
- **License metadata** ([#269](https://github.com/cyanheads/pubmed-mcp-server/issues/269)) — `pubmed_fetch_fulltext` PMC articles carry `licenses` (`{ text?, urls? }` per article-meta `<license>`), and `pubmed_europepmc_search` hits and `pubmed_europepmc_fetch` records carry Europe PMC's `license` string. Both render in `content[]`.

## Changed

- **Europe PMC full text is requested for open-access records** ([#267](https://github.com/cyanheads/pubmed-mcp-server/issues/267)) — gated on `isOpenAccess` and the record's `fullTextIdList` id, not on a PMCID. Open-access preprints now return full text, non-open-access records are no longer requested (they drew HTTP 500 and `service-error`), and `hasFullTextXml` follows the same rule.
- **Framework `@cyanheads/mcp-ts-core` 0.13.16** — tool error and enrichment-trailer text in `content[]` gains Markdown escapes ([cyanheads/mcp-ts-core#760](https://github.com/cyanheads/mcp-ts-core/issues/760)), and a handler that returns after its request was cancelled settles as `RequestCancelled` ([cyanheads/mcp-ts-core#753](https://github.com/cyanheads/mcp-ts-core/issues/753)). `structuredContent` is unchanged.

## Fixed

- **`pubmed_search_articles` sends the query as written** ([#260](https://github.com/cyanheads/pubmed-mcp-server/issues/260)) — `query` and the `author`, `journal`, `meshTerms`, `language`, and `publicationTypes` values reach ESearch with `&`, `<`, and `>` intact (`R&D[tiab]`, `c.1A>G`); only attribute-less inline formatting tags such as `<i>` are removed. `effectiveQuery`, `appliedFilters`, and `searchUrl` echo what was sent.
- **`pubmed_search_articles` `species: "animals"`** ([#270](https://github.com/cyanheads/pubmed-mcp-server/issues/270)) — appends `"animals"[mh:noexp]` instead of `animals[MeSH Terms]`, which exploded to Humans and admitted human-only studies.
- **`pubmed_search_articles` unmatched-phrase notice** ([#273](https://github.com/cyanheads/pubmed-mcp-server/issues/273)) — quotes `"zzqxw & yyqzv"[tiab]` as written, not with NCBI's double-encoded `&amp;`.
- **`pubmed_spell_check` indexed field values** ([#259](https://github.com/cyanheads/pubmed-mcp-server/issues/259)) — the value before an indexed field tag (`aged[mh]`, `zhang y[au]`, `free full text[sb]`) is kept as written; free-text tags such as `[tiab]` are still corrected.
- **Markdown in `content[]`** ([#261](https://github.com/cyanheads/pubmed-mcp-server/issues/261), [#263](https://github.com/cyanheads/pubmed-mcp-server/issues/263)) — values on lines that share a paragraph escape lone `*`, `` ` ``, `~`, and `_`, so no delimiter pairs across values. Caller echoes (`Effective Query`, applied filters, `pubmed_lookup_mesh` notices, Europe PMC pairs) render as code spans, `Search URL` as an autolink, and APA and MLA citations escape record text in both `content[]` and `structuredContent`.
- **Double-encoded entities in titles and abstracts** ([#262](https://github.com/cyanheads/pubmed-mcp-server/issues/262), [#272](https://github.com/cyanheads/pubmed-mcp-server/issues/272)) — ESummary titles and Europe PMC titles decode NCBI's residual entity layer (`Parkinson&apos;s` → `Parkinson's`); abstracts drop double-encoded tags, including `<br />` and `<p>`.
- **`pubmed_fetch_fulltext` one-letter back-matter fragments** ([#271](https://github.com/cyanheads/pubmed-mcp-server/issues/271)) — a section whose leftover `maxCharacters` allowance cannot hold its first word returns no text instead of a fragment; a single over-long token still gets its hard-cut prefix.
- **Europe PMC `core` journal** ([#274](https://github.com/cyanheads/pubmed-mcp-server/issues/274)) — `pubmed_europepmc_search` `core` hits and `pubmed_europepmc_fetch` records report `journal` from `journalInfo`.
