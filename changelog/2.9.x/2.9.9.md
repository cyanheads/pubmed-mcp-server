# 2.9.9 — 2026-07-26

## Added

- **`pubmed_lookup_mesh` offset pagination** — new `offset` input (default `0`) and `nextOffset` output let callers page past the `maxResults` cap; `nextOffset` is omitted on the last page as the end-of-results signal. ([#84](https://github.com/cyanheads/pubmed-mcp-server/issues/84))

## Changed

- **`pubmed_lookup_mesh` `totalCount`** now reports the true upstream match count from `eSearch`'s `count` field instead of the number of records returned on the page. ([#82](https://github.com/cyanheads/pubmed-mcp-server/issues/82))

## Fixed

- **`pubmed_lookup_mesh` pinned exact-match double-serve** — the exact-descriptor match is now held back on every page it ranks into, not just the first; a page consisting solely of the already-served pinned match returns an explanatory `enrichment.notice` instead of an empty or duplicated result. ([#91](https://github.com/cyanheads/pubmed-mcp-server/issues/91))
- **`pubmed_lookup_citation` false `author_mismatch` warning** — the mismatch check now verifies the queried author against the full author roster (`authorNames`) instead of the `authors` display string, which truncates to three names plus "et al." and was flagging genuine fourth-or-later authors as mismatches. `ESummaryDocumentSummary` parsing and `ParsedBriefSummary` gain an `authorNames: string[]` field alongside the existing `authors` display string. ([#87](https://github.com/cyanheads/pubmed-mcp-server/issues/87))
- **`pubmed_spell_check` dropped `ctx.signal`** — the handler now passes `{ signal: ctx.signal }` into `eSpell`, so request cancellation reaches the NCBI ESpell call. Also fixes a stale `pubmed_spell` log message to `pubmed_spell_check`. ([#89](https://github.com/cyanheads/pubmed-mcp-server/issues/89))
- **`pubmed_format_citations` description** — replaced "styles"/"style" with "formats"/"format" for accuracy.
- **Noisy error-path telemetry on expected 404s** — `expectedStatuses` added to the `fetchWithTimeout` call sites in `src/services/europe-pmc/api-client.ts` (404), `src/services/openalex/api-client.ts` (404), and `src/services/unpaywall/unpaywall-service.ts` (404, 422), so upstream responses these services already treat as expected "not found" outcomes no longer classify as errors.
